Dette technique

La métaphore

Ward Cunningham l'introduit en 1992 : un raccourci dans le code, c'est un emprunt.

  • on livre plus vite aujourd'hui
  • on paie des intérêts ensuite : chaque modification devient plus lente et plus risquée
  • on rembourse en remaniant le code

Sans remboursement, les intérêts finissent par absorber tout le temps de développement.

Technical Debt

Le quadrant de la dette

ImprudentePrudente
Délibérée« On n'a pas le temps de bien faire »« On livre maintenant, on sait ce qu'on devra reprendre »
Involontaire« C'est quoi, une couche ? »« Maintenant, on sait comment on aurait dû faire »

Seule la dette prudente et délibérée est un vrai choix. La dette prudente et involontaire est inévitable : on comprend le problème en le résolvant.

Dette et agent

  • L'agent imite le code qu'il lit : dans un projet endetté, il reproduit la dette.
  • Il produit beaucoup de code, vite : la dette s'accumule au même rythme.
  • Il ne rembourse rien de lui-même : il ne voit pas la dette, sauf si un capteur la lui signale.

Avec un agent, la dette technique devient involontaire et imprudente par défaut.

Code smells

Un code smell est un symptôme visible dans le code, qui signale un probable problème de conception.

  • le terme vient de Kent Beck, popularisé par Refactoring de Martin Fowler
  • un smell se repère vite, souvent à l'œil
  • il n'est pas toujours un problème : c'est une piste à examiner

Obsession des types primitifs

if ($ticket->getStatus() == 'closed') {
    // ...
}

if ($customer->getPlan() == 'premium') {
    $priority = $priority + 1;
}
  • des chaînes et des entiers « magiques », répétés dans tout le code
  • une faute de frappe ('close') ne provoque aucune erreur
  • rien n'indique la liste des valeurs possibles

Un enum PHP donne un nom, une liste fermée et un type à ces valeurs.

Obsession des types primitifs

enum TicketStatus: string
{
    case New = 'new';
    case InProgress = 'in_progress';
    case Resolved = 'resolved';
    case Closed = 'closed';
}

if ($ticket->getStatus() === TicketStatus::Closed) {
    // ...
}

Doctrine sait stocker un enum : #[ORM\Column(enumType: TicketStatus::class)]. La base garde les mêmes valeurs.

#[Route('/tickets/{id}/assign', methods: ['POST'])]
public function assign($id, Request $request): Response
{
    $ticket = $this->em->getRepository(Ticket::class)->find($id);
    if (!$ticket) {
        return new Response('Ticket introuvable', 404);
    }
    // vérifications métier, requêtes, changement de statut,
    // envoi de notification, message flash, redirection...
}
  • les règles métier ne sont réutilisables nulle part ailleurs : ni dans une commande, ni dans une API
  • elles ne se testent qu'à travers une requête HTTP
  • un agent qui ajoute une fonctionnalité voisine les recopie… ou les oublie

Mesurer la dette

Aujourd'hui, la dette se repère à l'œil. Les séances suivantes la mesurent :

style, idiomes datésPHP-CS-Fixer, Rector
types, méthodes inexistantesPHPStan
dépendances entre couchesDeptrac
comportement non vérifiéPHPUnit, Infection

Un outil mesure ce qu'une règle peut décrire. Une règle métier mal codée ne se voit qu'avec un test.
