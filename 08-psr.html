PSR-4 : autoloading

Un préfixe d'espace de noms correspond à un dossier ; la suite du nom de classe donne le chemin du fichier.

"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
ClasseFichier
App\Entity\Ticketsrc/Entity/Ticket.php
App\Controller\Api\TicketApiControllersrc/Controller/Api/TicketApiController.php
PSR-4 Composer : psr-4

PSR-4 : les pièges

  • un fichier dont le nom ne correspond pas à la classe n'est pas chargé
  • la casse compte : src/entity/Ticket.php fonctionne sous Windows et macOS, pas sur le serveur Linux
  • une seule classe par fichier

Composer signale les classes mal placées :

composer dump-autoload --strict-psr

Un agent qui crée un fichier au mauvais endroit produit une erreur Class not found… qu'il peut prendre pour un problème de cache.

composer dump-autoload

PER Coding Style

Le style de code du PHP-FIG, version 3.1. Il étend et remplace PSR-12, et suit les nouveautés du langage.

  • indentation de 4 espaces, jamais de tabulations
  • accolade ouvrante d'une classe ou d'une méthode seule sur sa ligne, celle d'une structure de contrôle sur la même ligne
  • elseif plutôt que else if, corps toujours entre accolades
  • mots-clés et types en minuscules, formes courtes (bool, int)
  • virgule finale obligatoire dans une liste sur plusieurs lignes
  • limite souple de 120 caractères par ligne

<?php

declare(strict_types=1);

namespace App\Service;

use App\Entity\Ticket;
use Psr\Clock\ClockInterface;

final class SlaCalculator
{
    public function __construct(
        private readonly ClockInterface $clock,
    ) {
    }

    public function isLate(Ticket $ticket): bool
    {
        if ($ticket->isClosed()) {
            return false;
        }

        return $this->dueDate($ticket) < $this->clock->now();
    }
}

Un standard ne s'applique pas à la main

  • personne ne vérifie 120 caractères ou la place d'une accolade en relecture
  • un agent suit le style du code qu'il lit, ou celui de ses données d'entraînement
