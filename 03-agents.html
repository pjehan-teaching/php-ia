Un agent enchaîne lui-même les actions pour accomplir une tâche.

La boucle de l'agent

flowchart LR
    P[Prompt] --> R[Raisonner]
    R --> A["Agir : lire, modifier, lancer une commande"]
    A --> O[Observer le résultat]
    O --> R
    R --> F[Réponse finale]

L'agent rassemble son contexte (code, erreurs, résultats de tests) au lieu de se fier à votre seul prompt, et itère jusqu'à estimer la tâche terminée.

Agents in VS Code

Agent = modèle + harnais

  • Le modèle (LLM) produit les réponses : il prédit la suite la plus probable.
  • Le harnais est tout ce qui l'entoure : instructions, outils, permissions, vérifications.

Une partie du harnais est fournie par l'éditeur de l'agent. L'autre, c'est vous qui la construisez pour votre projet.

Du code plausible

Un modèle produit le code le plus probable compte tenu de ses données d'entraînement et de ce qu'il a lu du projet.

Ce code compile, a l'air idiomatique et passe une relecture rapide.

Du code plausible n'est pas du code juste.

API disparue

#[Route('/tickets/{id}/comment', methods: ['POST'])]
public function comment(Request $request): Response
{
    $content = $request->get('content');
    // ...
}

Request::get() a été utilisée pendant des années… et n'existe plus en Symfony 8. Le code est plausible, l'erreur n'apparaît qu'à l'exécution.

À la place : $request->request->get() pour un champ de formulaire, $request->query->get() pour un paramètre d'URL.

Dépendance inventée

Une étude de 576 000 extraits de code générés par 16 modèles :

  • au moins 5,2 % des paquets suggérés n'existent pas avec les modèles commerciaux
  • 21,7 % avec les modèles open source
  • 205 474 noms de paquets inventés différents

Le slopsquatting consiste à publier un paquet malveillant sous l'un de ces noms, pour qu'un développeur ou un agent l'installe.

Spracklen et al., USENIX Security 2025

Pourquoi l'agent ne voit pas son erreur

  • Il ne connaît du projet que les fichiers qu'il a lus.
  • Il ne connaît des règles métier que celles qui sont écrites.
  • Il ne vérifie que ce qu'il peut exécuter : sans tests ni analyse statique, rien ne lui signale l'erreur.
  • Il s'arrête quand il estime avoir terminé.

Il faut lui dire quoi faire, et lui donner les moyens de vérifier ce qu'il a fait.
